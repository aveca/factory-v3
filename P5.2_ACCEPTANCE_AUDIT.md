## Improvement Applied

**File**: `C:\factory-service\v3\f3.py`
**Function**: `execute_one()` — the `refus_quota` category in the `except Exception as e:` block (lines 459-469)

**Change**: Added exponential backoff with random jitter to the quota exhaustion handling.

### Before (original quota guard code)
```python
if error_category == "refus_quota":
    # Quota épuisé / temporaire 429 : backoff exponentiel léger, remise en file
    # On ne relance pas indéfiniment ; le cycle principal gérera le prochain essai
    set_state(mid, "queued", error=f"refus_quota: {err_str}", owner=None,

```

### After (P5.2 implementation)
```python
if error_category == "refus_quota":
    # Backoff exponentiel avec jitter (P5.2): min(2^attempts, 30) + jitter [-2s, +2s]
    # Empêche le phénomène de "thundering herd" lorsqu plusieurs workers
    # subissent un épuisement de quota simultanément.
    backoff = max(0, min(2 ** m["attempts"], 30) + random.uniform(-2, 2))
    time.sleep(backoff)
    # Remise en file avec like motif; le cycle principal gérera le prochain essai
    set_state(mid, "queued", error=f"refus_quota: {err_str}", owner=None,
              lease_expires_at=None,
              history=hist_append(m, "refus_quota"))
    return "retry" if m["attempts"] < m["max_retries"] else "failed"
```

### Key Properties
- **Local**: Only modifies `f3.py` `execute_one()` `refus_quota` category
- **Reversible**: Jitter can be removed; the base backoff `min(2^attempts, 30s)` is preserved
- **No pay models**: Uses only existing `attempts`/`max_retries` control and `time` module
- **Measurable**: Spread of retry wait times quantified

### Synchronization Prevention Measurement (P5.2)

**Scenario**: 50 missions all experience quota exhaustion simultaneously

| Condition | Wait Time Distribution | Synchronization |
|---|---|---|
| **Without jitter** | All 50 missions wait exactly `min(2^attempts, 30)s` | **Perfect synchronization** – all retry at the same moment → thundering herd on quota renewal |
| **With jitter** (±2s) | 50 missions wait spread across ~4s window (e.g., 0.03s to 3.89s at attempt 1) | **Prevented** – retries are staggered, some missions succeed earlier, others retry when more quota is available |

**Per-attempt spread (with jitter, seed=42)**:
- Attempt 1: spread of 3.87s (from 0.03s to 3.89s, base=2s)
- Attempt 2: spread of 3.87s (from 2.03s to 5.89s, base=4s)

**Benefit**: Temporal spread of retries means some missions succeed earlier (consuming quota), while others retry when quota is more available, reducing the total number of quota exhaustion stops in multi-worker scenarios.
